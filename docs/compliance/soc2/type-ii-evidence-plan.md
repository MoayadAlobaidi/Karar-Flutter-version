# Type II Evidence Plan

**Status:** DRAFT · **Owner:** Compliance Owner · **Approver:** Platform Owner (pending) · **Version:** 0.2 · **Date:** 2026-08-15 · **Review:** every phase gate

**v0.2 (2026-08-15, Phase 2):** platform-foundation rows added (EV-201–EV-219 family); data-protection and logging rows updated now that their Phase-2 test evidence exists.

What evidence each control family must generate for a future Type II examination, at what frequency, collected how, owned by whom. **The observation window has not started and cannot start yet: it opens only when controls operate in production-relevant form** (for most families, Phase 17 at the earliest; for the full set, Phases 19–20). Until then, evidence collected is readiness practice — valuable as habit and as design proof, but not window evidence.

Frequencies: `per-PR` · `weekly` · `per-phase` · `continuous` (generated by the system as it runs) · `on-change`.

## Rules

1. **Every row lands in the [evidence register](../evidence-register.md) as EV entries when it first materializes** — this plan names types; the register tracks instances.
2. **Redaction before storage, always** — [evidence-handling.md](../evidence-handling.md) governs; evidence containing customer data is a defect in the evidence process itself.
3. **Sampling is honest:** "per-PR, sampled per-phase" means every PR generates it and the gate review examines a sample — the auditor will pick their own sample from the full population, so the population must be complete, not curated.
4. **A control's matrix status cannot exceed what its evidence row supports:** no evidence flowing → not OPERATING; evidence flowing but unreviewed → not EVIDENCED.
5. When the observation window is eventually planned with an auditor, this plan is re-baselined: window start date, population definitions, and sampling approach become part of the engagement, and readiness-era evidence is presented as design history, not window evidence.
