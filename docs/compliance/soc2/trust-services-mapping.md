Status shorthand: D = DESIGNED · I = IMPLEMENTED · I[C1] = implemented contingent on Phase-1 CI merge · I[P2] = implemented as Phase-2 code with tests run locally/CI, deployed nowhere · I[P3] = implemented as Phase-3 code with tests run locally against live PostgreSQL, deployed nowhere · I[P3.5] = implemented as Phase-3.5 code with tests executed locally against live PostgreSQL, deployed nowhere · I[P4] = implemented as Phase-4 client code and build-time guards, several of them asserted against a **real build artifact** rather than only against source, **installed on no device and deployed nowhere** · DEF = DEFERRED(phase) · EXC = exception.

**I[P4] is the weakest `I` in this file and the shorthand should not hide it.** An artifact assertion reads a merged manifest, an unzipped APK, or a packaged iOS bundle, which is stronger than reading source and still not a running application: **no Phase 4 control has been exercised on a device**, no build has been installed on one, and no build has been signed.

## Gaps this mapping makes visible

1. **CC7.2 has signals but no monitoring** (updated 2026-08-15): Phase 2 delivered the emitting half — audit trail, redacting telemetry, queue and readiness metrics — but nothing runs continuously, and alerting/on-call remain Phase 20 (KAR-RSK-003). The gap narrowed; it did not close. Phase 3 widened the signal set (security-event ledger, kill-switch history) without changing this.
