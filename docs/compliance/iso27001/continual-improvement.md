## What counts as a nonconformity

- A control practiced differently from its matrix statement without a recorded exception
- An exception whose exit trigger fired without action
- Evidence missing where the [evidence plan](../soc2/type-ii-evidence-plan.md) says it must exist
- A phase closed without its gate report, or a gate item silently skipped
- A published claim contradicting built reality (the P1 pattern — also an assurance-registry event)
- An incident post-review finding a control that failed as designed

Improvement opportunities (better control, cheaper evidence, clearer policy) are logged too, marked `OFI` rather than `NC` — they carry no corrective-action obligation, only an owner and a decision.

## Log schema

| Field | Meaning |
|---|---|
| `id` | `CI-###`, stable |
| `type` | `NC` (nonconformity) · `OFI` (improvement opportunity) |
| `source` | gate review · incident review · independent-reviewer-agent finding · external review · ad hoc |
| `description` | What was found, with the control/policy/register reference |
| `root cause` | For NC: why it happened — pattern-level, in the spirit of `docs/legacy/security-findings.md` §9 (root causes, not symptoms) |
| `correction` | The immediate fix |
| `corrective action` | The change that prevents recurrence (control edit, new test, process change) |
| `owner` | Role |
| `opened / due / closed` | Dates; due defaults to the next phase gate |
| `verification` | How closure was confirmed, by whom, when |
| `status` | `OPEN` · `IN_PROGRESS` · `CLOSED` · `ACCEPTED` (Platform Owner accepts without corrective action, with reason) |

## The improvement loop

1. **Find** — each phase gate reviews: gate report findings, incident post-reviews, reviewer-agent output, stale evidence, fired exception triggers.
2. **Log** — every finding lands here within the gate cycle that found it; an unlogged finding is itself an NC.
3. **Fix** — correction now, corrective action with an owner and a due gate; corrective actions that change controls flow into the [control matrix](../control-matrix.md) via PR.
4. **Verify** — closure requires named verification, recorded; the gate after the due date checks it.
   - **An entry closes only when its CORRECTIVE ACTION exists**, not when its correction worked. *(Added at the Phase 5 closeout, and it is CI-011's part (ii). CI-006 closed in 2026 on a register sweep run by hand that came back clean. The sweep was the correction; the corrective action was to make the sweep a check nobody has to remember, and that was deferred to a phase that had not started. Nothing in this schema stopped the entry reaching CLOSED with its preventive half still owed, so the log read CLOSED for a defect class whose fix had not been built — and the same class then recurred twice, as CI-011 and inside CI-017/CI-018.)*
   - An entry MAY close as **correction-only**, explicitly labelled, provided the corrective action is carried forward as **its own open entry with its own owner and due gate**. That is the difference between a decision and a disappearance.
   - **A due date that passes opens a nonconformity here at the next gate** rather than being re-dated (CI-016's rule). A third miss of the same corrective action opens one of its own.
5. **Learn** — recurring root causes (two NCs sharing one) escalate to the Platform Owner as a systemic item, per the legacy audit's own method.

## What a reviewer-agent finding is, and is not

Recorded once, because the log's honesty depends on it. The independent-reviewer step runs **before** a phase PR opens: it inspects the integrated diff and the registers, and its findings are remediated or formally deferred before merge. Most such findings are therefore **pre-merge defect detection, not nonconformities** — the control was never practised differently from its statement, because the divergence never reached the default branch.

A reviewer finding **is** an NC when it shows a control or register that *was already merged* behaving differently from its written statement, or a gate item that was skipped. Those are the entries below. Findings caught and fixed inside the phase are summarized against the phase they belong to, so the log carries the whole picture without inflating the NC count.

**And the meta-rule that produced CI-001:** whichever way a finding is classified, it must be *classified here*. Leaving the log empty is not a way of deciding that nothing qualified.
